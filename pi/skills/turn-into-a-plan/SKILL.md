# Turn into a plan

## Shape

1. Name the outcome in one sentence: what is true when the plan is done.
2. List what is already decided in the document. Do not re-plan those.
3. Break the work into 3–7 steps in the order they should happen. Each step is something a person can start today or this week, with a clear "done" condition.
4. Mark which steps depend on others and which carry the most risk. Put the riskiest uncertainty early.
5. Name the first action: the smallest concrete thing to do next.

## Hand back (finish)

- **answer**: the outcome line, then the numbered steps (each: what, done-when, and time or cost if it matters), then "First:" with the next action.
- Look up facts the plan depends on (prices, rules, tools, lead times) instead of guessing.
- **assumptions**: budget, time, people or tools you assumed.
- Keep it to one screen. A plan the user will not read is not a plan.
